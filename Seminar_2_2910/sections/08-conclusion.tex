We mapped how 49 papers at ICSE, FSE and ASE from 2024 to 2026 decide whether LLM-translated or migrated code behaves like the original. \new{Compilation (35 papers) and existing tests (28) dominate, while only 14 papers run the original program to compare behavior (RQ1). In translation between languages, tests come mostly from benchmarks, whereas library and version migrations run the project's own suite; none of the 5 papers with a legacy source uses existing tests, and 9 of the 12 papers on library migration include a human check (RQ2). Where papers report several oracles on the same outputs, the oracles disagree. In the 18 papers that give both a compile rate and a behavioral rate, behavior trails compilation by 3 to 98 percentage points, and in 4 of the 5 papers that report a similarity score next to a pass rate, the score reverses at least one ranking. Weak or few tests are the limitation that papers name most often, only 3 of the 17 papers with human evaluation report agreement between raters, and 10 papers state no limitation of their own oracle (RQ3).}

\new{The pilot shows the same effect when only the oracle varies. Depending on the oracle and its threshold, 52\% to 90\% of one fixed set of 164 translations count as correct, and at least one of the three oracles that do not execute the code disagrees with the tests on 46\% of the tasks. A small LLM judge accepts half of the translations that fail the tests and rejects 41\% of the benchmark's own reference solutions (RQ4). A reported success rate therefore describes the oracle as much as the technique.}

\new{Measured against what a migration needs, evidence that the migrated code behaves like the original, current practice leaves five gaps (RQ5): compile rates and similarity scores diverge from behavioral results (G1); judgments by people or LLMs are rarely validated (G2); test evidence for translation rests largely on benchmarks (G3); some tests are not independent of the system under evaluation (G4); and most studies do not run the original program (G5). The Oracle Provenance Checklist in Section~\ref{sec:checklist} turns these gaps into seven items that studies can report and reviewers can check, and the directions in Section~\ref{sec:rq5} raise the questions that better reporting alone cannot answer, such as which oracles catch which faults. These findings hold for three venues over three years (Section~\ref{sec:threats}).} Before we trust LLMs to translate the software that runs the world, we must agree on how to check their work; \new{the checklist} is a first step.

\paragraph{Data availability.} \new{The replication package is available at \url{https://github.com/Nov17th/llm-code-migration-oracles} (release \fillin{v1.0}). For the map, it contains the search log with dates and counts for every proceedings volume, the codebook, every screening decision with its reason and evidence basis, the extraction form and coded data for all 51 papers, the data behind every table and figure, and a script that recomputes every count in the paper. For the pilot, it contains the harness that applies the four oracles, its checks on the reference solutions and seeded faults, the prompts, the verdict of every oracle on every task, and the executed notebook of the run with the model digests and dataset hashes.}
